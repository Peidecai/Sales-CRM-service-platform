# ============================================================
# AI 智能 CRM 销售管理系统 — Claude 自动化审查任务清单
# ============================================================
# 基于 docs/chapters 01-13 设计文档，为 Claude Code CLI 生成审查任务。
# 用法示例（计划/只读模式）：
#   cd crm-sales-platform
#   claude-auto.ps1 所在目录下：
#   .\claude-auto.ps1 -TaskFile .\claude-review-tasks.txt -PermissionMode plan -MaxTurns 40
#
# 约定：
# - 每一行是一个独立审查任务提示词（中文），Claude 将在当前仓库中执行代码审查。
# - Claude 应读取对应的 docs/chapters/chapterXX.md 文档，并对照实际代码实现给出结论。
# - 输出为 Markdown 报告，直接打印在终端即可（不强制写文件）。
# - 重点关注：是否符合设计、是否有缺失功能、是否有实现偏差与风险。
# ============================================================

# ============ Ch.1 系统总体设计 — 全局一致性审查 ============

请阅读 docs/chapters/chapter01.md《系统总体设计》，结合 README.md 与实际代码结构，
从「功能目标、性能目标、扩展性、安全性、可运维性」这五个维度，全面审查当前代码仓库是否符合总体设计。
要求：输出一份 Markdown 审查报告，按模块（认证、客户管理、销售流程、呼叫中心、AI 分析、销售信息管理、运维）列出：
1) 已完全符合的点（PASS）；2) 部分符合但有差距的点（WARN，说明差距与影响）；3) 明显不符合或缺失的点（FAIL，给出文件路径和建议）。

# ============ Ch.2 前端设计规范 — Vue3 实现审查 ============

请阅读 docs/chapters/chapter02.md《前端设计规范》，审查 packages/web/src 前端实现是否与规范一致。
重点检查：目录结构(api/router/stores/views)、状态管理(Pinia)、路由守卫、请求封装(Axios)、权限指令(v-permission)、UI 组件(Element Plus)、表单与校验、国际化/主题等。
要求：输出一份前端代码审查报告，按章节 2.x 的结构列出：
- 规范已落实的点（附关键文件路径）；
- 与规范不一致或缺失的实现（说明影响和整改建议）；
- 建议补充的 eslint/prettier/vitest 配置改进点。

# ============ Ch.3 后端设计规范 — NestJS 架构审查 ============

请阅读 docs/chapters/chapter03.md《后端设计规范》，对 packages/server/src 的 NestJS 后端进行全面架构审查。
重点检查：模块划分(common/config/modules)、Controller/Service/Repository 职责分离、DTO 与校验、异常与错误码、拦截器与中间件、日志与审计、缓存与队列(Bull)、配置管理(ConfigService) 等。
要求：输出一份后端架构审查报告，按照 chapter03 中的大纲逐条对照：
- 标记每一条规范是「严格遵守 / 部分遵守 / 未遵守」；
- 对于「部分遵守/未遵守」的项，列出具体文件和代码片段位置，并给出重构建议优先级（P0/P1/P2）。

# ============ Ch.4 数据库设计 — 实体与迁移审查 ============

请阅读 docs/chapters/chapter04.md《数据库详细设计》，对照 packages/server/src/modules 下的实体(Entity) 与 database/migrations 下的迁移文件。
重点检查：表名/字段命名规范(snake_case、_at 后缀)、主键/外键/索引/唯一约束、金额/时间/状态字段类型、软删除实现方式、字段默认值与非空约束等。
要求：输出一份数据库设计落地情况报告：
- 列出已经完全符合规范的关键表（如 customers/opportunities/call_records 等）；
- 列出命名或字段类型与设计不一致的表和字段，并说明可能的业务/性能风险；
- 给出一份建议的 Migration 改造清单（仅列出变更思路，不必写 SQL）。
