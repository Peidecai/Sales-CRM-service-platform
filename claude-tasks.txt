# ============ Ch.6 销售流程管理 — 缺失模块 ============

请按照设计文档 chapters/chapter06.md 的报价管理部分，在 packages/server/src/modules/ 下创建 quotation 模块。包含：QuotationEntity（quotations 表）、QuotationItemEntity（quotation_items 表）、QuotationController（CRUD + 审批提交）、QuotationService、CreateQuotationDto/UpdateQuotationDto，以及对应的 TypeORM Migration。实体字段参考 chapter06.md 中报价管理的数据模型。控制器需要 JwtAuthGuard + RolesGuard，DELETE 限制 Admin/Manager。同时在 packages/web/src/api/ 下创建 quotation.ts API 封装文件。

请按照设计文档 chapters/chapter06.md 的合同管理部分，在 packages/server/src/modules/ 下创建 contract 模块。包含：ContractEntity（contracts 表，字段包含 opportunity_id/customer_id/contract_no/title/amount/start_date/end_date/status/signed_date/file_url 等）、ContractController（CRUD + 签署确认 + 到期预警列表）、ContractService、CreateContractDto/UpdateContractDto，以及 TypeORM Migration。控制器遵循项目 CLAUDE.md 中的守卫和审计日志规范。同时在 packages/web/src/api/ 下创建 contract.ts API 封装。

请按照设计文档 chapters/chapter06.md 的回款管理部分，在 packages/server/src/modules/ 下创建 payment 模块。包含：PaymentPlanEntity（payment_plans 表）、PaymentRecordEntity（payment_records 表，字段含 contract_id/plan_id/amount/payment_date/payment_method/status/confirmed_by 等）、PaymentController（创建回款计划、确认到账、逾期列表查询）、PaymentService，以及 TypeORM Migration。同时在 packages/web/src/api/ 下创建 payment.ts API 封装。

请按照设计文档 chapters/chapter06.md 的审批流程部分，在 packages/server/src/modules/ 下创建 approval 模块。包含：ApprovalFlowEntity（approval_flows 表，定义审批流模板）、ApprovalRecordEntity（approval_records 表，含 flow_id/applicant_id/status/current_step/data_snapshot）、ApprovalStepEntity（approval_steps 表）、ApprovalController（发起审批、审批/驳回/撤回）、ApprovalService。TypeORM Migration + packages/web/src/api/approval.ts API 封装。审批完成后通过 NotificationService 发送通知。

# ============ Ch.6 销售漏斗 — 统计 API + 前端页面 ============

请为 opportunity 模块补充销售漏斗统计 API。在 OpportunityService 中添加 getSalesFunnel() 方法，按商机阶段（初步接触/需求确认/方案提报/商务谈判/赢单/丢单）统计数量和金额，计算阶段转化率。在 OpportunityController 中添加 GET /api/v1/opportunities/funnel 端点（需 JwtAuthGuard）。响应格式为 { stages: [{ stage, count, amount, conversionRate }], totalAmount, winRate }。在前端 packages/web/src/views/opportunity/ 下创建 funnel.vue 页面，使用 ECharts 或 Element Plus 组件展示漏斗图。

# ============ Ch.13 部署与运维 — Docker 生产配置 ============

请检查并完善 packages/server 的 Dockerfile（如果不存在则按 chapter13.md 创建）。要求：多阶段构建（builder + runner），使用 node:18-alpine，COPY pnpm-lock.yaml 并安装依赖，构建产物 COPY 到 runner 阶段，暴露 3000 端口，使用非 root 用户运行。同时检查 docker-compose.yml 中 server 服务是否正确引用该 Dockerfile，确保 depends_on mysql/redis，环境变量通过 .env 注入。

请为前端创建或完善 packages/web 的生产 Dockerfile：多阶段构建，第一阶段 node:18-alpine 执行 pnpm build，第二阶段 nginx:alpine 复制 dist/ 到 /usr/share/nginx/html，COPY nginx 配置文件处理 Vue Router history 模式的 try_files。检查 docker/web/ 下 nginx.conf 是否已有对应配置。
