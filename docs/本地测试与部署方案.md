## 1. 环境前置条件

| 工具           | 最低版本   | 检查命令                 |
| -------------- | ---------- | ------------------------ |
| Node.js        | ≥ 18.0.0   | `node -v`                |
| pnpm           | ≥ 8.0.0    | `pnpm -v`                |
| Docker Desktop | ≥ 24.x     | `docker -v`              |
| Docker Compose | V2（内置） | `docker compose version` |
| Git            | 任意       | `git -v`                 |

> **Windows 用户注意**：确保 Docker Desktop 已开启 WSL2 后端，否则 MySQL 容器可能出现权限问题。

## 2. 方案 A：开发模式（本地调试）

**适用场景**：日常编码、调试、热重载开发。

### 2.1 安装依赖

```bash
cd crm-sales-platform
pnpm install
```

### 2.2 启动中间件（MySQL + Redis）

```bash
docker compose up -d mysql redis
```

等待健康检查通过：

```bash
docker compose ps
# 期望看到 mysql (healthy)、redis (healthy)
```

### 2.3 配置环境变量

```bash
# Windows
copy .env.example .env

# Linux / macOS
cp .env.example .env
```

`.env` 文件内容参考：

```env
NODE_ENV=development
DB_HOST=localhost
DB_PORT=3306
DB_USERNAME=root
DB_PASSWORD=crm_password_123
DB_DATABASE=crm_sales
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_PASSWORD=
REDIS_DB=0
JWT_SECRET=dev-jwt-secret-for-local-testing-only
JWT_ACCESS_EXPIRES_IN=2h
JWT_REFRESH_SECRET=dev-jwt-refresh-secret-for-local-testing-only
JWT_REFRESH_EXPIRES_IN=7d
```

> 注意：`database.config.ts` 中已有开发默认值，本地无 `.env` 也可启动。

### 2.4 运行数据库迁移

```bash
cd packages/server
pnpm migration:run
cd ../..
```

### 2.5 启动服务

打开两个终端窗口分别运行：

**终端 1 — 后端**（NestJS，端口 3000）：

```bash
pnpm dev:server
```

**终端 2 — 前端**（Vite，端口 5173）：

```bash
pnpm dev:web
```

### 2.6 验证

| 验证项   | 方法                                                                | 预期结果                              |
| -------- | ------------------------------------------------------------------- | ------------------------------------- |
| 健康检查 | `curl http://localhost:3000/api/v1/health`                          | `{ code: 0, data: { status: "ok" } }` |
| 前端页面 | 浏览器打开 `http://localhost:5173`                                  | 看到登录页                            |
| 登录测试 | 用 `admin / admin123` 登录                                          | 成功跳转到仪表盘                      |
| API 代理 | 前端发起 `/api/*` 请求                                              | Vite 自动代理到 `:3000`               |
| Swagger  | 设置 `SWAGGER_ENABLED=true` 后访问 `http://localhost:3000/api/docs` | 看到 API 文档                         |

```

│  Vue 3 (Vite)   │ ───────────────────▶ │  NestJS Server   │
```

## 3. 方案 B：Docker 全栈模式（模拟生产）

**适用场景**：模拟生产环境、验收测试、给测试人员/PM 演示。

### 3.1 配置环境变量

在项目根目录创建 `.env`：

```env
DB_PASSWORD=crm_password_123
JWT_SECRET=your-64-char-random-jwt-secret-string-here
JWT_REFRESH_SECRET=your-64-char-random-jwt-refresh-secret-string-here
DASHSCOPE_API_KEY=sk-your-dashscope-key
CORS_ORIGINS=http://localhost
```

生成安全密钥：

```bash
node -e "console.log(require('crypto').randomBytes(64).toString('base64'))"
```

### 3.2 一键构建并启动

```bash
docker compose up --build -d
```

> 首次构建约 3~5 分钟（下载镜像 + 安装依赖）。后续构建有 Docker 缓存。

### 3.3 等待所有服务就绪

```bash
docker compose ps
```

期望状态：

```
NAME          STATUS                 PORTS
crm-mysql     running (healthy)      0.0.0.0:3306->3306
crm-redis     running (healthy)      0.0.0.0:6379->6379
crm-server    running (healthy)      0.0.0.0:3000->3000
crm-web       running                0.0.0.0:80->80
```

查看实时日志：

```bash
docker compose logs -f server
```

### 3.4 数据库迁移（首次部署）

```bash
docker compose exec server sh -c "cd /app/packages/server && npx typeorm migration:run -d database/data-source.ts"
```

### 3.5 验证

| 验证项    | 方法                                       | 预期结果                       |
| --------- | ------------------------------------------ | ------------------------------ |
| 前端页面  | 浏览器打开 `http://localhost`              | 登录页（通过 Nginx :80）       |
| API 代理  | `curl http://localhost/api/v1/health`      | Nginx 转发到后端，返回健康状态 |
| WebSocket | 登录后检查浏览器控制台                     | `/ws/notifications` 连接成功   |
| 后端直连  | `curl http://localhost:3000/api/v1/health` | 绕过 Nginx 直连后端            |

### 3.7 停止与清理

```bash

docker compose down -v

# 仅重新构建某个服务
docker compose up --build -d server
```

## 4. 方案 C：混合模式（推荐日常开发）

**适用场景**：本地开发代码 + Docker 运行数据库，兼顾热重载和环境一致性。

```bash
# 1. 只启动中间件
docker compose up -d mysql redis

# 2. 等待健康检查通过
docker compose ps

# 3. 运行数据库迁移（首次）
cd packages/server && pnpm migration:run && cd ../..

# 4. 本地运行后端（热重载）
pnpm dev:server

# 5. 本地运行前端（热重载，新终端窗口）
pnpm dev:web
```

> 这是日常开发最推荐的模式：Docker 保证中间件版本一致，同时享受代码热重载。

## 5. 测试策略

### 5.1 后端单元测试（Jest）

```bash
# 运行全部后端测试
pnpm --filter @crm/server test

# 带覆盖率
pnpm --filter @crm/server test -- --coverage

# 监听模式（文件变更时自动重跑）
pnpm --filter @crm/server test:watch

# 仅运行匹配文件名的测试
pnpm --filter @crm/server test -- --testPathPattern="auth"
```

配置说明：

- 框架：Jest 29 + ts-jest
- 无需真实 MySQL/Redis（测试中使用 Mock 或 better-sqlite3）
- 覆盖率报告输出到 `packages/server/coverage/`

### 5.2 前端单元测试（Vitest）

```bash
# 运行全部前端测试
pnpm --filter @crm/web test
```

配置说明：

- 框架：Vitest（集成在 Vite 中）
- 运行环境：happy-dom
- 测试文件匹配：`src/**/*.{test,spec}.ts`
- 覆盖率范围：`utils/`、`composables/`、`stores/`、`directives/`

### 5.3 E2E 测试（Playwright）

```bash
# 安装浏览器（首次执行）
npx playwright install chromium --with-deps

# 运行 E2E 测试（自动启动 Vite 开发服务器）
pnpm test:e2e

# 带 UI 的交互模式
pnpm test:e2e:ui
```

配置说明：

- 测试目录：`e2e/`
- 基准 URL：`http://localhost:5173`
- API 调用通过 `page.route()` 拦截，**不需要真实后端**
- CI 中仅运行 Chromium，失败重试 2 次
- 失败时自动截图 + trace 记录

### 5.4 完整测试流水线（本地模拟 CI）

按 CI 流水线顺序依次执行：

```bash
pnpm --filter @crm/shared build                        # 1. 构建共享包
pnpm lint                                               # 2. 代码检查（ESLint）
pnpm --filter @crm/server test -- --ci --coverage       # 3. 后端单元测试
pnpm --filter @crm/web test                             # 4. 前端单元测试
pnpm --filter @crm/server build                         # 5. 后端构建
pnpm --filter @crm/web build                            # 6. 前端构建
npx playwright test                                     # 7. E2E 测试
```

### 5.5 手动 API 测试

使用 curl 手动测试各接口：

```bash
# 1. 登录获取 Token
TOKEN=$(curl -s -X POST http://localhost:3000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' | jq -r '.data.accessToken')

echo "Access Token: $TOKEN"

# 2. 健康检查
curl -s http://localhost:3000/api/v1/health | jq

# 3. 获取客户列表（需认证）
curl -s http://localhost:3000/api/v1/customers \
  -H "Authorization: Bearer $TOKEN" | jq

# 4. 获取商机列表
curl -s http://localhost:3000/api/v1/opportunities \
  -H "Authorization: Bearer $TOKEN" | jq

# 5. 获取通话记录
curl -s http://localhost:3000/api/v1/call-records \
  -H "Authorization: Bearer $TOKEN" | jq

# 6. 获取知识库列表
curl -s http://localhost:3000/api/v1/knowledge \
  -H "Authorization: Bearer $TOKEN" | jq

# 7. 获取审计日志
curl -s http://localhost:3000/api/v1/audit-logs \
  -H "Authorization: Bearer $TOKEN" | jq

# 8. 刷新 Token
REFRESH_TOKEN=$(curl -s -X POST http://localhost:3000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' | jq -r '.data.refreshToken')

curl -s -X POST http://localhost:3000/api/v1/auth/refresh \
  -H "Content-Type: application/json" \
  -d "{\"refreshToken\":\"$REFRESH_TOKEN\"}" | jq
```

| `admin`   | `admin123` | Admin | 全部功能 + 用户管理             |

## 7. 常见问题排查

### Q1: MySQL 容器启动失败

```bash
# 查看日志
docker compose logs mysql

# 常见原因：端口 3306 被占用
netstat -ano | findstr :3306

# 解决方案：停掉本地 MySQL，或修改 docker-compose.yml 端口映射
# ports: "3307:3306"
# 同时修改 .env 中 DB_PORT=3307
```

### Q2: `pnpm install` 失败（better-sqlite3 编译错误）

```bash
# Windows 需要 C++ 构建工具
# 方法 1：安装 Visual Studio Build Tools（C++ 桌面开发工作负载）
# 方法 2：
npm install -g windows-build-tools

# package.json 已配置 pnpm.onlyBuiltDependencies 仅编译 better-sqlite3
```

### Q3: 数据库迁移失败

```bash
# 确认数据库容器运行中
docker compose ps mysql

# 确认 crm_sales 数据库已创建
docker compose exec mysql mysql -uroot -pcrm_password_123 -e "SHOW DATABASES;"

# 重新执行迁移
cd packages/server && pnpm migration:run
```

### Q4: 前端 API 请求 404

```bash
# 确认后端已启动
curl http://localhost:3000/api/v1/health

# Vite 代理配置位于 packages/web/vite.config.ts
# proxy: { '/api': { target: 'http://localhost:3000' } }
# 确保后端运行在 3000 端口
```

### Q5: Docker 全栈模式下前端白屏

```bash
# 检查 Nginx 日志
docker compose logs web

# 检查构建产物
docker compose exec web ls /usr/share/nginx/html/

# 常见原因：shared 包构建失败，导致前端构建失败
# 重新构建
docker compose up --build -d web
```

### Q6: Redis 连接失败

```bash
# 检查 Redis 是否运行
docker compose exec redis redis-cli ping
# 期望返回: PONG

# 开发模式下确保 .env 中 REDIS_HOST=localhost（不是 redis）
# Docker 全栈模式下 REDIS_HOST=redis（容器名）
```

### Q7: WebSocket 连接失败（Docker 全栈模式）

```bash
# 确认 nginx.conf 包含 /ws/ 代理配置
docker compose exec web cat /etc/nginx/conf.d/default.conf | grep -A 5 "/ws/"

# 验证 WebSocket 升级
curl -i -N \
  -H "Connection: Upgrade" \
  -H "Upgrade: websocket" \
  -H "Sec-WebSocket-Version: 13" \
  -H "Sec-WebSocket-Key: $(openssl rand -base64 16)" \
  http://localhost/ws/notifications/

# 期望响应：HTTP/1.1 101 Switching Protocols
```

### Q8: Docker 构建速度太慢

```bash
# 确认 .dockerignore 文件存在且排除了 node_modules
cat .dockerignore

# 使用 BuildKit 加速（Docker Desktop 默认已启用）
DOCKER_BUILDKIT=1 docker compose up --build -d

# 仅重建变更的服务
docker compose up --build -d server   # 仅重建后端
docker compose up --build -d web      # 仅重建前端
```

## 8. 三种模式对比

| 维度                 | 方案 A（开发模式）    | 方案 B（Docker 全栈）  | 方案 C（混合模式）     |
| -------------------- | --------------------- | ---------------------- | ---------------------- |
| **热重载**           | ✅ 前后端均支持       | ❌ 需重建镜像          | ✅ 前后端均支持        |
| **环境一致性**       | ⚠️ 依赖本地 Node 版本 | ✅ 与生产环境一致      | ⚠️ 代码层依赖本地 Node |
| **启动速度**         | 快（秒级）            | 慢（首次分钟级）       | 快（秒级）             |
| **适用场景**         | 日常编码              | 验收 / 演示 / 集成测试 | **日常开发（推荐）**   |
| **前端地址**         | `localhost:5173`      | `localhost:80`         | `localhost:5173`       |
| **后端地址**         | `localhost:3000`      | `localhost:3000`       | `localhost:3000`       |
| **所需 Docker 服务** | mysql + redis         | 全部 4 个              | mysql + redis          |
| **Nginx 代理**       | 无（Vite 代理）       | ✅ 有                  | 无（Vite 代理）        |
| **WebSocket 测试**   | 直连后端              | 经 Nginx 代理          | 直连后端               |

## 总结

| 场景           | 推荐方案                                                       |
| -------------- | -------------------------------------------------------------- |
| 日常功能开发   | **方案 C**（Docker 中间件 + 本地代码热重载）                   |
| 提测 / 演示    | **方案 B**（Docker 全栈，一键 `docker compose up --build -d`） |
| 运行单元测试   | 无需 Docker，直接 `pnpm test`                                  |
| 运行 E2E 测试  | 无需后端，Playwright 拦截 API，直接 `pnpm test:e2e`            |
| 模拟 CI 流水线 | 按 5.4 节顺序依次执行                                          |
