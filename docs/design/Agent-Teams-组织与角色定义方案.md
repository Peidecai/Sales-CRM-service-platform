## 1. 方案概述

### 1.1 目标

基于 Claude Code 的 **Agent Teams** 实验功能，将项目开发拆分为 **6 支虚拟团队**，每支团队由 1～2 个 Agent 角色承担，明确职责边界、技能要求、使用工具与技术栈，便于按阶段启动 Teammate 并协同交付本 CRM 项目。

### 1.2 启用 Agent Teams

```bash
export CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=true
claude
```

### 1.3 与本项目的关系

| 项目维度   | 说明                                                                                                  |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| 业务范围   | AI 智能 CRM 销售管理系统（客户管理、销售流程、呼叫中心、AI 分析、销售信息管理、微信小程序）           |
| 技术栈基准 | 前端 Vue 3 + Vite + Element Plus；后端 NestJS + TypeORM；数据库 MySQL 8 + Redis；部署 Docker + 阿里云 |
| 文档依据   | 《技术栈与环境要求文档》《AI智能CRM销售管理系统详细设计文档》及 chapters 各章                         |

## 3. 管理团队

### 3.1 项目经理（Project Manager）

| 维度         | 内容                                                                                                                                                                          |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **职责范围** | 制定与维护项目计划（WBS、里程碑、依赖）；协调各 Agent 任务优先级与交付顺序；跟踪进度与风险，输出周报/站会纪要；组织评审与发布决策；管理文档版本与变更（需求变更、范围控制）。 |
| **技能范围** | 敏捷/Scrum 基础、甘特与依赖管理、风险识别与缓解、跨角色沟通、文档结构化（Markdown/表格/清单）。                                                                               |
| **实用工具** | 任务列表（TodoWrite）、Markdown 文档（排期表、风险清单、会议纪要）、分支与标签策略（Git）、与产品/架构的接口（需求文档、技术方案文档）。                                      |
| **技术栈**   | 不涉及编码；需理解 Monorepo 结构、分支策略（main/develop/feature）、CI 阶段含义。                                                                                             |

---

### 3.2 产品经理（Product Manager）

| 维度         | 内容                                                                                                                                                           |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **职责范围** | 梳理与维护产品需求（用户故事、验收标准、优先级）；编写 PRD/功能说明，与设计、开发对齐；参与原型与交互评审；验收功能是否满足需求；管理需求 backlog 与迭代范围。 |
| **技能范围** | 需求分析与拆解、用户故事与验收标准编写、竞品与用户场景理解、CRM 业务域（客户生命周期、销售漏斗、公海池、呼叫与 AI 分析）。                                     |
| **实用工具** | PRD/功能说明（Markdown）、用户故事与验收清单、与设计/开发的接口（设计稿说明、API 行为描述）、需求追溯（故事 ↔ 模块/接口）。                                    |
| **技术栈**   | 不涉及编码；需理解模块划分（客户/销售/呼叫/AI/信息管理/小程序）、API 与前端能力边界。                                                                          |

## 4. 设计团队

### 4.1 UI/UX 设计大师（UI/UX Design Lead）

| 维度         | 内容                                                                                                                                                                                           |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **职责范围** | 制定并维护设计规范（色彩、字体、间距、组件样式）；输出关键页面与流程的交互说明与视觉规范；设计系统组件与业务组件的外观与状态；与前端对齐实现细节（响应式、无障碍、性能）；参与设计评审与走查。 |
| **技能范围** | 视觉设计、交互设计、设计系统、响应式布局、可访问性（a11y）、CRM 类后台与数据密集型界面设计经验。                                                                                               |
| **实用工具** | 设计规范文档（Markdown + 色板/字体表/间距表）、组件状态说明、Figma/Sketch 导出或标注说明（可文字描述）、与前端约定的 class/ token 命名。                                                       |
| **技术栈**   | 与实现强相关：Element Plus 组件体系、Vue 3 单文件组件、SCSS 变量与 Mixin、Vite 与主题注入；了解 ECharts 图表与数据可视化约定。                                                                 |

## 5. 架构团队

### 5.1 软件架构师（Software Architect）

| 维度         | 内容                                                                                                                                                                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **职责范围** | 确定系统分层与模块划分（前端/后端/共享）；定义模块间接口契约（API 路径、DTO、事件）；设计数据库 Schema 与 Migration 策略；制定安全、性能、可观测性等非功能方案；评审关键实现与重构建议；维护架构决策记录（ADR）与技术债务清单。                                  |
| **技能范围** | 分层架构、领域建模、API 设计（REST/OpenAPI）、数据库建模与索引策略、安全与合规（认证、授权、审计）、高可用与扩展性。                                                                                                                                             |

| **技术栈**   | **后端**：NestJS、TypeORM、MySQL 8、Redis、Bull、Passport/JWT、Swagger。**前端**：Vue 3、Vite、Pinia、Vue Router、Element Plus。**运维**：Docker、Docker Compose、Nginx、阿里云（ECS/RDS/OSS/SLB）。**共享**：TypeScript 严格模式、pnpm workspaces、共享类型包。 |

## 7. 质量保障团队

### 7.1 代码审核员（Code Reviewer）

| 维度         | 内容                                                                                                                                                                               |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **职责范围** | 对提交的代码进行规范性、安全性、可维护性评审；检查是否符合架构分层与接口契约；发现潜在 bug、性能问题与重复代码；推动最佳实践与统一风格；输出评审意见与改进项，必要时给出修改示例。 |
| **技能范围** | 代码规范（ESLint/TS 严格模式）、安全（XSS、注入、敏感信息）、设计模式与分层、可读性与命名、测试与边界情况考虑。                                                                    |
| **实用工具** | ESLint/Prettier 报告、Git diff/PR 视图、静态分析结果、架构与接口文档、安全清单（OWASP 等）、CLAUDE.md 与 ADR。                                                                     |
| **技术栈**   | 需熟悉本项目前后端技术栈（Vue 3、NestJS、TypeORM、Redis），以便判断实现是否合理；不强制写代码，但能读懂并建议修改。                                                                |

## 9. 协作流程与启动方式

### 9.1 阶段与团队参与建议

| 阶段       | 参与角色（建议）         | 产出概要                           |
| ---------- | ------------------------ | ---------------------------------- |
| 需求与规划 | 产品经理、项目经理       | PRD、排期、里程碑                  |
| 设计与架构 | 产品、UI/UX、架构师      | 设计规范、架构图、接口契约、Schema |
| 开发       | 架构师、前端、后端       | 功能代码、API、前端页面            |
| 质量保障   | 代码审核员、测试工程师   | 评审意见、用例、自动化、质量报告   |
| 发布与运维 | DevOps、架构师、项目经理 | 流水线、环境、发布与监控           |

### 9.2 Agent 启动示例（按角色）

在启用 Agent Teams 后，可按任务类型启动对应 Teammate，例如：

```text
# 管理
/teams start "根据 PRD 拆解本周迭代任务与优先级" --name pm-iteration

# 设计
/teams start "按设计规范输出客户列表页的组件状态与响应式断点说明" --name ui-spec

# 架构
/teams start "评审客户模块 API 与 DTO 是否符合 REST 与安全规范" --name architect-review

# 开发
/teams start "实现客户公海池领取与回收接口及前端页面" --name backend-customer
/teams start "实现客户列表页筛选、分页与导出" --name frontend-customer

# 质量
/teams start "对客户模块做代码评审并列出改进项" --name code-review
/teams start "编写客户模块接口测试与关键路径 E2E 用例" --name qa-automation

# 运维
/teams start "在 CI 中增加客户模块的单元与接口测试门禁" --name devops-pipeline
```
