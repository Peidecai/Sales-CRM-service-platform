## 3. 通话与拨号 (Call)

APP 支持两种外呼模式，可并存：

| 模式                      | 枚举                | 说明                     | 通话录音                        |
| ------------------------- | ------------------- | ------------------------ | ------------------------------- |
| **方案B: 手机原生外呼**   | `CallType.MANUAL`   | 调起系统拨号，轻量级     | ❌ 不可录，通话后语音速记补充   |
| **方案D: 云呼叫中心回呼** | `CallType.CALLBACK` | 服务端发起回呼，三方通话 | ✅ 云端全程录音 + ASR + AI 分析 |

> **通话录音说明**: iOS/Android 系统层面禁止第三方 APP 录制通话音频，这不是框架限制。需要通话录音必须走云呼叫中心（方案D），通话在服务端建立，录音在云端完成。

### 功能清单

| 功能            | 说明                              | 优先级 | 接口                                    |
| --------------- | --------------------------------- | ------ | --------------------------------------- |
| 一键外呼 (原生) | 客户详情页直接拨号 (方案B)        | P1     | `uni.makePhoneCall`                     |
| 云呼回呼        | 服务端发起回呼，云端录音 (方案D)  | P1     | `POST /api/v1/cloud-call/initiate`      |
| 双卡切换        | 选择外呼 SIM 卡 (APP 专属, 方案B) | P1     | Plus API                                |
| 通话后记录      | 通话结束自动弹窗填写结果+备注     | P1     | `POST /api/v1/call-records`             |
| 语音速记        | 录音备注 → ASR 转文字 → 保存      | P1     | `POST /api/v1/recordings/upload`        |
| 通话录音回放    | 播放云端通话录音 (方案D)          | P1     | `GET /api/v1/cloud-call/:id/recording`  |
| 通话记录列表    | 客户维度通话历史                  | P1     | `GET /api/v1/call-records?customerId=`  |
| AI 通话分析     | 查看 AI 摘要/评分/意向            | P1     | `GET /api/v1/call-records/:id/analysis` |
| 拍照取号        | OCR 识别照片中电话号码            | P2     | 本地 OCR                                |
| 外呼模式切换    | 用户选择默认外呼方式 (原生/云呼)  | P1     | 本地 Storage                            |

### 方案B: 手机原生外呼流程

适用场景: 无需通话录音的日常沟通、网络条件差时。

```
用户点击 [📞 拨号] → 选择"直接拨号"
  → callState.setPendingCall({ customerId, customerName, phone })
  → 双卡选择 (APP) / 直接拨号 (小程序)
  → uni.makePhoneCall({ phoneNumber })
  → APP 进入后台
  → 通话结束，APP 回到前台 (App.onShow)
  → 检测 callState.pendingCall
  → 弹出 after-call 浮层
  → 用户填写: 通话结果 / 备注 / 语音速记入口
  → 提交 → callState.clearPendingCall()
```

### 方案D: 云呼叫中心回呼流程

适用场景: 需要通话录音、AI 实时分析、合规存档的重要客户沟通。

```
用户点击 [📞 拨号] → 选择"云呼录音"
  → POST /api/v1/cloud-call/initiate {
      customerId, customerPhone, callerPhone
    }
  → 服务端调阿里云CCC/天润 API 发起回呼
  → 云端先呼销售手机 → 销售接听
  → 云端再呼客户 → 客户接听 → 三方通话建立
  → 通话全程在云端录音
  → 通话结束 → 云端回调 webhook
    → POST /api/v1/cloud-call/callback {
        callId, duration, recordingUrl, status
      }
    → 异步: 录音文件下载 → ASR 转写 → AI 分析 (Bull Queue)
  → APP 收到 WebSocket/Push 通知 "通话分析完成"
  → 用户查看: 录音回放 + AI 摘要 + 评分 + 意向分析
```

### 云呼叫中心架构

```
┌─────────┐        ┌──────────────┐        ┌───────────────┐
│  APP    │ ──→   │ @crm/server  │ ──→   │ 云呼叫中心     │
│ 发起呼叫 │        │ CloudCall    │        │ (阿里云CCC/   │
│         │        │ Module       │        │  天润/容联)    │
└────┬────┘        └──────┬───────┘        └───────┬───────┘
     │                    │                        │
     │  ← 先呼销售手机 ←──┤←── 回呼销售 ←──────────┤
     │  ← 再呼客户 ←─────┤←── 回呼客户 ←──────────┤
     │                    │                        │
     │                    │  ← 通话结束回调 ←───────┤
     │                    │  ← 录音文件 URL ←──────┤
     │                    │                        │
     │                    ├── ASR 转写 ──→ AI 分析  │
     │                    │                        │
     │ ← Push/WS通知 ←───┤                        │
     │  "分析完成"        │                        │
└─────────┘        └──────────────┘        └───────────────┘
```

| 值             | 含义                | 适用    |
| -------------- | ------------------- | ------- |

### 跟进记录离线流程

```
无网络 → 写入 offline-queue (max 50)
  → uni.onNetworkStatusChange 检测恢复
  → 逐条 flush → POST /api/v1/follow-ups
  → 失败重试 3 次 → 超过丢弃
```
