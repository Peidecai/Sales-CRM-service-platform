# Specs

Use specs for changes where the target behavior or acceptance criteria need to
be explicit before implementation.

## When To Write A Spec

- new user-facing feature
- cross-package workflow
- database or API contract change
- AI behavior change
- ambiguous business request
- refactor with behavior-preservation requirements
