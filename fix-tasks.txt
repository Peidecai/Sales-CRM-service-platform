# T01 — customer-pool 模块实体边界修复

5. 不修改 CustomerPoolService/CustomerPoolController 的业务逻辑，仅修改模块定义文件。

# T03 — AiModule 实体边界（CallRecord + Customer 跨模块注册）
请修复 packages/server/src/modules/ai/ai.module.ts 中直接注册跨模块实体的问题。
当前 AiModule 在 TypeOrmModule.forFeature([...]) 中直接注册了 CallRecord（属于 CallRecordModule）和 Customer（属于 CustomerModule）。
背景约束：AiModule 被 KnowledgeModule 导入，而 KnowledgeModule 中的实体（KnowledgeArticle）也被 AiModule 的 processors 使用，存在潜在循环依赖风险。
修复方案：
1. 先读取 packages/server/src/modules/ai/ai.module.ts 文件查看当前完整内容。
2. 在 ai.module.ts 的 imports 中加入 CallRecordModule（来自 ../call-record/call-record.module，需要使用 forwardRef(() => CallRecordModule)，因为 CallRecordModule 可能导入 AiModule）和 CustomerModule（来自 ../customer/customer.module）。
3. 从 TypeOrmModule.forFeature([...]) 中移除 CallRecord 和 Customer 实体。
4. 对 KnowledgeArticle 的处理：若 KnowledgeModule 导入 AiModule，而 AiModule 需要 KnowledgeArticle，需使用 forwardRef(() => KnowledgeModule) 导入 KnowledgeModule，并在 KnowledgeModule 中用 forwardRef(() => AiModule) 导入 AiModule。若 KnowledgeArticle 已在 KnowledgeModule 的 exports TypeOrmModule 中可用，则直接去掉 forFeature 中的 KnowledgeArticle 注册。
5. 修改完成后检查 TypeScript 编译是否通过：cd packages/server && pnpm build 2>&1 | tail -20。如有循环依赖报错，改用 forwardRef 包装。
